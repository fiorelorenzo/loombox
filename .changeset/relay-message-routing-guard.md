Issue #691: a `WireMessageV1` member missing from `relay.ts`'s `handleDeviceMessage`/`handleNodeMessage`/`handleClientMessage` routing switches used to be dropped with no error, no warning and no log — the relay's own default branches were silent, and every unit test stayed green. A new `message-routing.ts` exports `MESSAGE_ROUTES`, a `{ [T in WireMessageV1['type']]: MessageRoute }` mapped type classifying every wire message as routed by one of the three switches (`device` / `node` / `client` / `node-and-client`), handled before any switch is reached (`handshake`, i.e. `initialize`), or genuinely `not-routed` with a stated reason (a relay-constructed reply the relay itself sends and never receives, e.g. `pong`, `initialize_result`, `target_list`). Adding a member to the wire union without adding a matching `MESSAGE_ROUTES` entry now fails `tsc`; `message-routing.test.ts` reads `relay.ts`'s own source and cross-checks every switch's actual `case` labels against what's declared, in both directions, so a wrong (not just missing) entry fails `pnpm test` too. The two switches' `default` branches also now log at `error` instead of `warn` (still just logging — no thrown error, no behavior change for anything that already routes correctly).
