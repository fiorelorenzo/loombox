Wire message reachability: derived exhaustiveness check, plus a real `schemasV1` gap it found (issue #910)

Nothing enforced that a new v1 wire message was actually reachable through `wireMessageV1` — the closest thing was a hand-maintained `messagesByType` fixture map covering 30-ish of the (now) 208 union members, plus scattered per-family "slots into the union" assertions in 11 of 44 test files. The gap was not hypothetical: the fine-grained-PAT-paste slice (#224) shipped its message registered in the union, in `index.ts`'s exports, and in the relay's routing table, but missing from `schemasV1` — caught only by an agent manually re-verifying a wip commit, not by any test.

**Reachable, defined precisely (named in `message.test.ts`'s new `describe('reachability (issue #910)', ...)`):** a v1 wire message type is reachable when it is (1) _registered_ — its schema is a `wireMessageV1.options` member AND that exact object is one of `schemasV1`'s values, (2) _decodable_ — a fixture parses through `wireMessageV1` and reports back the same `type`, or the type is named in an explicit, reasoned `NOT_YET_FIXTURED` allowlist, and (3) _routable_ — `packages/relay/src/message-routing.ts`'s `MESSAGE_ROUTES` (already a mapped type exhaustive over `WireMessageV1['type']`, so this leg was already compiler-enforced) names a role or an explicit `not-routed` reason.

- The registered/decodable checks are derived from `wireMessageV1.options` itself, never a hand-written list — a type present in neither `messagesByType` nor `NOT_YET_FIXTURED` fails immediately, and a type missing from `schemasV1` fails immediately (`findUnregisteredSchemas`, itself proven to catch a real absence by a regression test that deliberately drops a real `schemasV1` entry and asserts the check reports it).
- Ran the sweep and fixed what it found: `schemasV1` (`packages/protocol/src/v1/index.ts`) was silently missing 41 of 208 union members' schemas — nine entire families (`rewind`, `git-diff`, `git-diff-explain`, `git-hunks`, `git-branch`, `git-push`, `git-stash`, `git-commit`, `heartbeat`) were never imported into the file's own registry-construction section at all, plus partial gaps in `fs.ts` (the whole read side) and `terminal.ts` (`terminal_resync_marker`). Added the missing imports and every one of those families' schemas to `schemasV1`, not just the narrower set of exact union members the derived test requires.
- The 52 v1 types with zero prior test coverage (issue #910's own literal sweep) are now all fixtured with valid instances in `messagesByType` and parsed through `wireMessageV1` by the existing "routes every fixtured v1 message family" test. The remaining 121 union members not yet in `messagesByType` (each already exercised by its own family's test file, just not consolidated here) are named individually in `NOT_YET_FIXTURED` with the covering file, so a genuinely new, uncovered member can never hide among them.

Verified: `pnpm --filter @loombox/protocol exec vitest run src/v1/message.test.ts` (12 tests), full `pnpm --filter @loombox/protocol exec vitest run` and full `pnpm test` (touches `packages/protocol`), `pnpm --filter @loombox/protocol typecheck`, `pnpm --filter @loombox/relay typecheck`, `pnpm exec eslint` on every changed file, full `pnpm format:check`.
