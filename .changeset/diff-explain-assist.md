AI diff-explain assist: explain a hunk or a whole file's diff via the session's own agent (SPEC §7.6, issue #236)

I built this on #233's own precedent instead of a second path: the explanation comes from the session's own live agent through `bridge.agentSession.prompt()`, never a new provider call, and it is read-only. It never stages, discards, or commits anything.

Scope of input is the real judgement call here. A whole diff can be enormous, and sending an unbounded blob wastes tokens and can push a session toward its context ceiling, the exact thing #250 just made visible to the user. I bounded it: `packages/node/src/git-diff-explain.ts` exports `MAX_EXPLAIN_DIFF_TEXT_CHARS` (20,000 characters), applied to whichever scope's own diff text `computeExplainDiffText` produces, right before it reaches the prompt. This is deliberately narrower than `git-commit.ts`'s own 200,000-byte staged-diff cap, since a single file or a single hunk is inherently smaller than a whole staged index by construction. An oversized file or hunk still explains, just from a truncated view, same as `computeStagedDiffText`'s own contract.

What I added:

- `packages/protocol/src/v1/git-diff-explain.ts`: a new `git_diff_explain_request`/`git_diff_explain_response` pair. `scope` is a discriminated union, either `{ kind: 'file', path }` (every current staged+unstaged hunk for that path, concatenated) or `{ kind: 'hunk', path, side, hunkIndex }` (exactly one hunk, addressed the same way `git_hunk_action_request` addresses one). Enveloped both ways, unlike `git_diff_request`/`git_hunk_diff_request`: the scope names a real path, so it is genuine session content, mirroring `git_hunk_action_request`'s own reasoning.
- `@loombox/relay`'s `message-routing.ts` and `relay.ts` route the request to the owning node and fan the response out to a session's subscribed clients, exactly like `git_hunk_action_request`/`git_commit_request`. The relay never sees the path, the hunk, or the explanation text.
- `packages/node/src/git-diff-explain.ts`: `computeExplainDiffText` reuses `git-diff.ts`'s `computeHunkDiff` for both scopes rather than a second `git diff` invocation, so an untracked file's synthetic hunk is explainable for free. `buildDiffExplainPrompt` builds the literal prompt text.
- `NodeDaemon.handleGitDiffExplainRequest`/`explainGitDiffForBridge`/`explainDiffViaAgent`/`sendGitDiffExplainResponse` in `node-daemon.ts`, appended as one contiguous block at the end of the class rather than interleaved next to `handleGitCommitDraftRequest`, since this wave lands several git/AI-assist issues in the same file at once. `explainDiffViaAgent` is a deliberate copy of `draftCommitMessageViaAgent` rather than a shared extraction, for the same reason. A session with no live agent (archived, or disconnected since a restart) reports `outcome: 'error'` with a clear message instead of hanging, the same contract #233's draft path has.

I left the web UI out of this PR. The wave's own acceptance criteria for #236 are entirely backend-observable (a fixture agent, the prompt's shape, the no-live-agent contract, the bound), and `apps/web/src/lib/relay-client.ts` is one of the two files this wave's own brief names as the highest merge-conflict risk. Wiring an explain button through it belongs in its own change once the git-AI-assist wave has landed and that file has settled.

Tests: `git-diff-explain.test.ts` in both `packages/protocol` and `packages/node` (schema round-trips; a real local git repo for hunk/file/untracked-file extraction, a stale hunkIndex, a missing path, and the truncation boundary itself, checked both just under and exactly at the cap). `node-daemon.test.ts` adds a `git-diff-explain` suite: explaining a hunk and explaining a file's diff each drive a real echo-fixture agent turn over the real wire, with a spy on the live `bridge.agentSession.prompt` asserting the actual prompt text sent (the scope description, the real added/removed lines, the "ONLY the explanation" instruction), plus the no-live-agent contract via the same reload-after-restart pattern `config_option`'s own #702 test uses. `relay.test.ts` adds routing/fan-out/unknown-session coverage matching `git_hunk_action_request`'s own describe block, and `message-routing.test.ts` (already exhaustive over the wire union) confirms the new routing table entries match the real switch cases.

Verified: `pnpm --filter @loombox/protocol exec vitest run src/v1/git-diff-explain.test.ts src/v1/message.test.ts` (26 tests), `pnpm --filter @loombox/node exec vitest run src/git-diff-explain.test.ts src/node-daemon.test.ts` (105 tests), `pnpm --filter @loombox/relay exec vitest run src/relay.test.ts src/message-routing.test.ts` (200 tests), `pnpm --filter @loombox/protocol typecheck`, `pnpm --filter @loombox/node typecheck`, `pnpm --filter @loombox/relay typecheck`, `pnpm exec eslint` on every changed file (clean), and the full `pnpm format:check` (clean).
