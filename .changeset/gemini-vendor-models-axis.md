Gemini's vendor `models` axis now surfaces as a selectable config-option category (issue #844, filed by #272's build-time verification spike)

Gemini CLI's real `session/new`/`session/load` response carries a `models` sub-object (`{availableModels: [{modelId, name, description?}], currentModelId}`) structurally identical to the ACP-baseline `modes` sub-object, paired with a separate `unstable_setSessionModel` method (wire name `session/set_model`) rather than the ordinary `session/set_config_option`. `mapConfigOptions` never read it, so `ConfigBar` (issue #711) had no way to show or change which Gemini model a session uses, even though Gemini's own response advertises the exact same shape both `modes` already gets folded from.

- `packages/providers/core/src/client.ts`: `mapConfigOptions` now folds a wire `models` sub-object into a `'model'`-category `AcpConfigOption`, the same way it already folds `modes` into `'mode'` — used only when `configOptions` has no `'model'` entry of its own, so an agent that already advertises `model` as an ordinary `configOptions` entry (e.g. a real `omp acp` binary) is completely unaffected, and an agent that sends neither `configOptions` nor `models` gets no `'model'` category synthesized from nothing. The synthesized entry's `type` is a new module-private sentinel (`unstable_model`), not `'select'`, so it never gets misrouted through `session/set_config_option` — Gemini's real `GeminiAgent` class implements no such method at all.
- `AcpClient.setConfigOption` now branches on that sentinel: a `'model'` category folded from the vendor `models` field routes through the real `session/set_model` request (`{sessionId, modelId}`) instead, and — since that method's response carries no catalog to reapply, unlike `session/set_config_option`'s always-echoed `configOptions` — applies the new selection to the session's own catalogue entry directly once the agent acks. A rejected request (e.g. an unknown `modelId`) still rejects the promise and leaves the stored selection untouched, same as the ordinary path.
- No UI change: `apps/web`'s `ConfigBar` already renders every non-`mode` category generically (issue #711's consolidated popover), so feeding it a `model` entry from this fold is the whole fix. The wire protocol (`@loombox/protocol`'s `acpConfigOptionV1`) never carries `id`/`type` to the browser in the first place, so this vendor detail stays entirely server-side, inside `packages/providers/core`.
- New fixture `packages/providers/core/test/fixtures/gemini-like-acp-agent.mjs`, shaped after Gemini's real ACP surface at the exact commit `agent-catalogue.ts`'s `gemini-cli` entry targets (`a74b483d`, GitHub's `v0.54.0` tag) and cross-checked against the real `@agentclientprotocol/sdk@0.16.1` package gemini-cli 0.54.0 depends on (its generated zod schema independently declares the identical `SessionModelState`/`ModelInfo`/`session/set_model` shape) — see the fixture's own header for the full citation trail, including what is and isn't a verified claim.
