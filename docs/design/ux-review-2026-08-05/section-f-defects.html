Files and Terminal die for good after the node restarts

nella workbench il tab files non funziona. [...] il terminale spesso non funziona

Both, same cause, and it is the bug I already fixed once. A node keeps a SessionBridge per live session, created in exactly one place (node-daemon.ts:1905, inside session creation) and never rebuilt for a session that was already on disk. Eleven handlers open with if (!bridge) return; — fs_list_request (:2836), terminal_open (:3947), terminal input/resize/close, the three test-runner handlers, run_start, run_cancel and prompt_inject. So the moment the node restarts — a deploy, a crash, a reboot — every pre-existing session keeps rendering its transcript from the client's own cache while every one of those requests is dropped without a reply. The client waits out its own 10s deadline (FileTreePanel.svelte:82, InteractiveTerminal.svelte:293) and then blames the node for being asleep or offline, which is exactly the wrong thing to tell you: the node is awake, connected, and ignoring you.

This is the same defect class as #697, the tracker bug you found last round. That fix removed the guard on one handler and left the other eleven. The comment it left behind at :2922-2925 even says so out loud. Better yet, the terminal handler's own doc comment promises the opposite of what the code does: “so the client never hangs waiting for a reply that never comes”, three lines above the return that hangs it.

And the node already knows. A session reloaded from disk after a restart comes back marked 'disconnected' on purpose, with the reasoning written out at session-manager.ts:49-53: “a node restart means the agent process that made a saved 'running' or 'paused' record true is simply gone, and pretending otherwise would let a client believe it can resume into a live agent that no longer exists”. That is exactly right, and then nobody tells you. The client draws the session like any other, offers Files and Terminal, and the handlers meet both with silence — so the one honest piece of state in the system never reaches the screen.

The tool-call glyph sits below the line it belongs to

le icone dei comandi eseguiti di quando esegue un tool non sono allineate con il testo del comando

Real, and it is one declaration. .tool-gutter carries padding-top: var(--space-2xs) (ToolCallGutter.svelte:27) inside a row that is already align-items: flex-start. The row aligns the gutter's top edge to the command's top edge correctly, and then that padding pushes the glyph 4px down from it, so it lands between the first and second line instead of on the first. The padding is decorative; the gutter's real job, keeping the glyph flush to the column's right edge, is done by align-items: flex-end and is unaffected by removing it.

TodayGlyph 4px low

Reads as sloppy at every width, and worse on a one-line command where there is no second line for the eye to forgive it against.

▸
$ git status -sb && git log --oneline -12
dashed line = the command's first text line
FixDrop the padding

Glyph and command share one baseline; nothing else in the row moves.

▸
$ git status -sb && git log --oneline -12
same row, padding removed

The terminal prints its own plumbing before your prompt

quando funziona ci sono delle righe in alto di testo prima della riga per i comandi che non c'entrano niente

Found it, with one honest caveat. On an SSH target the node writes cd <worktree> && clear into the shell channel and only then wires the output listeners (node-daemon.ts:4049, listeners at :4053), so that command and whatever the login shell printed before it are already in the buffer when the client attaches. The code comment calls this “an accepted, documented tradeoff”; you are the evidence that it is not accepted. It exists because ssh2's shell channel has no cwd option, unlike a local node-pty spawn.

The caveat: your session is a local target, and the local branch has no such write — I opened a terminal on it and got a single clean prompt row and nothing else. So either you saw this on an SSH target, or there is a second source I have not reproduced. Worth one sentence from you before I fix the wrong thing.
