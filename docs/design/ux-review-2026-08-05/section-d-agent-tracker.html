This is an information-architecture change only, not a data one. Issue #697 (merged, live) already made tracker records project-addressed — trackerProject carries only {nodeId, projectPath} (:603, :1121, :2001-2004) and TrackerPage takes client/projectPath/nodeId with no session argument at all (:2655-2683's own comment). The data layer is ready; nothing about the transport changes below, only where the entry point sits. .topbar today is a two-zone justify-content: space-between flex with no centre slot (:4774-4828), so "verso il centro" needs a real three-zone layout, not a middle child bolted onto the existing one — C1-1 shows what happens when someone takes the shortcut instead. Every mock below that isn't Today assumes C1 has already landed as C1-1 (tabs always in the topbar, its widest variant) for the right zone — the honest worst case for crowding; C1-2 or C1-3 would leave more room than shown here. On the sidebar's own Tracker destination row (:2671-2683): every option below keeps it, demoted rather than deleted, for two reasons that hold regardless of which option wins — it is still the only way into Tracker for a project with no session open (the switch itself, like today's Workbench/Terminal, only exists once a session is selected), and the mobile tabbar has no Tracker slot of its own (Sessions / Inbox / Command only, :3645-3687), so the sidebar sheet stays its only route there too.
