Not a missing feature — a broken wire. ConfigBar already exists as SPEC.md §7.24 “Model, mode & reasoning effort”'s specified home for exactly these two controls, mounted in the one row under the composer since Lorenzo's own July 30 request put it there. It renders only the agent name and the cost meter today — I read the live DOM and it is literally Oh My Pi + $0.00 — because options is always empty. client.ts:432 seeds every new session from this.lastConfigCatalog, and that field is populated only by initialize (:408); session/new's own response is typed as a bare { sessionId: string } (:427), so whatever catalogue it carries is never even parsed. Probed against the real omp acp binary directly: initialize returns no configOptions at all — session/new is where the real catalogue lives, 26 models, thinking (off/auto/low/medium/high/xhigh/max), mode (default/plan). There's a shape to bridge too: the wire sends {id,name,category,type,currentValue,options:[{value,name,description}]}, the internal AcpConfigOption (types.ts:158) is {category,current,choices:[{id,name}]}. Read session/new's response and map that shape, and “le opzioni giuste per ogni provider” comes for free — the agent declares its own catalogue per provider; loombox's only job is to stop discarding it and render whatever arrives. What's left to decide is presentation: 26 models and 7 thinking levels is a lot to fit under one composer row. Every option below also carries a second, orthogonal fork: session/set_config_option changes the running session only — nothing in the client persists a choice past it, so a “remember for new sessions” checkbox is new plumbing, not a flip of a switch that already exists.
