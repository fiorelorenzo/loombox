How a turn is delimited

non mi piacciono le card dei messaggi dell'utente e dell'agente. Per niente.

Both roles get a filled, rounded box. .message-item.user sets background: var(--color-surface-raised), border-radius: var(--radius-md) and padding-inline (MessageItem.svelte:402-406), and its gutter also draws box-shadow: inset 2px 0 0 0 var(--color-accent) (:409-411). .message-item.agent/.thought get the same radius and padding on --color-surface instead (:421-427). The component's own comment admits the redundancy for the user's case: "the user's own second, redundant cue: the raised surface plus this accent bar, so no single mark carries the whole distinction alone" (:396-401). But .gutter + .content is already the one device that says "this is a turn" (v6 spec §3.4) — the fill repeats that same idea in a second, boxier shape. The spec's own words for the tool-call case never got applied here: "one level of card chrome, not two" (2026-08-03-cockpit-v6-design.md:175).

Two structures mark the same boundary: the box and the bar. Neither one can be pointed to as the delimiter — both are.

The per-row copy button

non mi piacciono le card dei messaggi dell'utente e dell'agente. Per niente.

Every row — user, agent, thought — renders CopyButton with revealOnHover (MessageItem.svelte:317-319). At rest it is fully transparent on a hover-capable pointer (CopyButton.svelte:146-148) and sits at opacity: 0.7 permanently on touch (:155-159); hovering or focusing the row brings it to full opacity (MessageItem.svelte:673-676, CopyButton.svelte:150-153). Invisible chrome is still chrome: it reserves a slot at the end of every single turn, and every row pays that layout cost even when nobody ever hovers it.

Zero visual cost at rest, one reveal per row on hover — but the slot itself, and the layout gap it reserves, exists on every turn regardless of whether it's ever used.
