B1

A status bar at the bottom

Today the shell has no status bar at all: a resizable session sidebar (collapsible to an icon rail, +page.svelte:2700-2714), the topbar, the canvas, an optional right-hand workbench panel (:3345, :3649-3658) and, as a sibling of the whole shell rather than a fourth column, the terminal dock (:3778-3809). Every signal Zed would put in a status bar exists in loombox today, just scattered and mostly hidden: relay connection is a chip that only renders when there is a notice to show (connectionNotice, :3222-3241) — invisible the instant the connection is healthy. Target/node health is a single boolean alert dot on the account avatar and the Settings menu row (hasUnhealthyTarget, :3047-3095); the actual per-target detail behind it (targetHealthDots, :1803-1811) never reaches the cockpit. Build identity (#655) compares the relay's own version/commit against every connected node and renders a Behind badge — but only on that node's own row inside TargetStatusView on the Settings page (TargetStatusView.svelte:276-280), never near a session. Session state is one of eight real values (error, permission_required, working, starting, awaiting_input, queued, disconnected, exited — +page.svelte:1956-1965), shown as a single StatusDot per row in the sidebar list (:2563-2566) and nowhere for the one session actually open in the canvas. The context/cost meter lives inside ConfigBar, itself inside the composer strip at the bottom of the canvas (ConfigBar.svelte:534-564, mounted +page.svelte:3593-3597). A queued session (the 'queued' status above) gets the same invisible sidebar dot as everything else.

TodayNo status bar — every signal lives somewhere else, mostly hidden

Nothing wrong with any one of these signals on its own, but there is no single place that answers "is everything OK right now" without opening Settings, hovering a dot, or waiting for a notice to appear.

B1-1Add a real status bar, and name what goes left and right

Left: relay connection, target health, build identity's Behind badge — the three things about the machine underneath the session. Right: this session's own state, the context/cost meter (moved out of ConfigBar), a queued-session count. The bar earns its permanent 24-ish px band by retiring the conditional topbar chip and the avatar's boolean dot outright — one home instead of three half-homes. The cost is that a status bar is chrome for the whole window in Zed, not just the session view: it has to render (mostly quiet) on the inbox, settings and tracker pages too, or it stops being "the instrument reads at a glance" and starts being "the session view has extra furniture."

Tabs over the canvas

Today one canvas shows exactly one session's transcript (<ol class="items">, +page.svelte:3433-3462); there is no tab strip anywhere over it. Files/Config/Runner is a role="radiogroup" inside the right panel's own header (:3667-3690) — v8 C1-3 settled that this group stays there and does not move to the topbar, and nothing here reopens it. There is also, today, no way to actually open a file's content at all: clicking a file in the tree only inserts an @-mention into the composer (onSelectFile={insertFileReference}, :3705-3709) — the only place a file's content ever renders is inside whatever edit/diff card the agent itself produces. Zed's centre pane is a real tab strip: files, diffs, the agent thread, terminals, each its own tab, splittable. In Lorenzo's screenshots two file tabs sit next to the agent thread: README.md and Preview README.md.

B2-1Keep single-canvas, on purpose

Nothing to build, and on a phone there is nothing to lose either, since there was never a strip to collapse. The cost stands exactly as described above: a file is only ever visible through the agent's own diff card, never on demand, never side by side with the thread.

B2-2A tab strip for opened files and diffs, transcript pinned leftmost and non-closable

The session transcript keeps its permanent front-row seat; a file you open (from the tree, from an @-mention, from a diff card's "open full file") gets a real tab next to it, closable, with a dirty indicator when the agent's own edit touched it since you last looked. Below the 768px tablet breakpoint (TABLET_VIEWPORT_BREAKPOINT_PX, viewport.ts:17) a horizontal strip has nowhere to go: it would have to become a single active tab plus a picker (a sheet, a dropdown), which is a different, unbuilt design wearing this one's name.

B2-3Full pane model — the transcript is just another tab, sessions can split

Closest to Zed itself: no tab is special, a session can open beside another session or a file in a split. Costs the most on a phone by a wide margin — a split assumes two panes visible at once, which does not exist under 768px at all, so every split has to serialize into full-screen panes with their own back-stack, and "the transcript is just another tab" means a session can lose its own front-row seat on a phone unless a separate rule pins it back, a rule B2-2's model never needed because it never let the transcript be one tab among equals in the first place.

Because loombox sessions always run against a target — local or remote — "where" already matters more here than in Zed, where local is the unmarked default.

B4

The empty canvas

Measured at 1728px on the running app: with no session selected, or a session with one turn, roughly 70% of the canvas is empty space (_research.md §7.3). The "no session selected" gate renders the shared EmptyState — a dimmed 14%-opacity BrandMark, one sentence, an optional CTA (EmptyState.svelte:33-39,42-60) — only for that one gate (+page.svelte:3390-3431). A session with one or two turns gets no zero-state treatment at all: it renders the exact same <ol class="items"> + .canvas-footer path as any transcript (:3433-3524). .items is flex: 1 and top-aligned, not centered (:5175-5187), while .canvas-footer stays pinned to the bottom via flex-shrink: 0 (:5240-5248) — so a short transcript just leaves the flex space between the last turn and the composer blank. Zed fills the same space with thread history and a keyboard-hint block.

TodayDimmed mark + one sentence, and only for "no session"

B4-1Keep the current EmptyState, unchanged

Cheapest possible pick — zero work — but it only ever covers the "no session selected" gate. The more common case, a brand-new session with one or two turns (every session, every time, for a while), keeps exactly the same blank flex space it has today.

B4-2A real zero state: recent sessions, the last transcript's tail, the bindings that matter

Recent sessions for this project reuse the sidebar's own sessions/ projects derivation — no new data source. The bindings are real, not invented: ⌘K jump to (isModShortcut(event,'k'), :2247-2249), ⌘B toggle the sessions sidebar (:2257-2259), ⌘. stop the running turn (:2252-2254), Esc defer a permission (research digest §6). The cost: this is now real surface with its own empty-of-that case — a brand new project with no prior sessions has nothing "recent" to show, and it has to stay honest when a session truly has zero turns yet, with no tail to preview.
