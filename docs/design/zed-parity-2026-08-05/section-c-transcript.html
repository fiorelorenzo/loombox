Today's composer placeholder still promises exactly one thing: Enter to send · Shift+Enter for a new line · @ to reference a file (+page.svelte:3575-3576). That promise is kept, and it is the whole feature. FileReferencePicker is fully wired: imported at +page.svelte:82, mounted at :3903-3908, opened by handleComposerInput the moment you type @ (:1678-1690), and a pick runs through insertFileReference (:1703-1713), which splices a literal @path string into the draft text at the caret. The tool row: icon, duration, tokens

v7 settled the one-line shape and is not being reopened here: a completed call rests as one line, command plus outcome, disclosure closed (C1-1), and a failure force-expands (C2-1). What is open is what shares that one line. loombox already has per-kind icon infrastructure, but only two tool kinds actually use it: the tier-1 bespoke table is 'edit-write' | 'bash' | 'todo' | 'generic' (tool-widgets.ts:22), and only tool-edit and tool-bash exist as distinct glyphs (icon-paths.ts:57-59 lists exactly tool-bash, tool-edit, tool-generic). Every other ACP tool kind, read, search, fetch, delete, move (acp-wire-schema.ts:44-54), falls through to GenericToolRow, which hardcodes icon="tool-generic" regardless of the real kind (GenericToolRow.svelte:163): a search call and a fetch call render the same wrench glyph. Status tone already exists per call (TOOL_CALL_STATUS_TONES, tool-widgets.ts:186-191), so that part is free. Duration is not: TranscriptToolCallItem carries id, turnId, title, toolKind, status, diff, rawInput, content, parentToolCallId (transcript.ts:38-49) and nothing that looks like a timestamp; ACP itself never sends a start or end time for a tool call. Token attribution is also not there: usage_update "is session-level (no per-tool attribution)" (SPEC.md:1656), a flat {used, size, cost} with no link to any tool call at all.
